TSB Multi-agent RL for in-orbit servicing
Problem Method Benchmark Workstreams Team

Servicer satellites that talk only when it matters.

We’re benchmarking multi-agent reinforcement learning for in-orbit servicing and testing Targeted Selective Broadcasting (TSB), where each agent learns when to send a message and who should receive it.

The problem

A team of servicer satellites shares a neighborhood of clients that need refueling, inspection or repair, with debris moving through the same space. Every servicer has limited fuel and a limited view, so the team has to divide the work without crashing, doubling up, or leaving clients waiting.

Talking helps, but bandwidth in orbit is scarce and links drop. Telling everyone everything floods the channel. Saying nothing leads to duplicated trips. We want agents that learn the middle ground.

We model relative motion with Clohessy-Wiltshire (Hill) dynamics in a space robotics layer built on an existing simulator, not a simulator written from scratch.

How TSB works

TSB sits inside each agent’s policy. Every step, a message passes through three learned stages before anything goes on the channel.

  1. Gate

    A Gumbel-softmax switch decides whether this agent has anything worth sending right now.

  2. Target scorer

    Attention over teammates picks who should hear it, usually one or two agents rather than all of them.

  3. Message encoder

    Turns the agent’s observation into a compact message, trained end to end with the policy.

Trained together

MAPPO with a centralized critic that sees the full state during training. The gate and targets are learned as PPO actions, with a communication cost that anneals up from zero.

Flown apart

At execution each servicer acts only on its own observation plus the messages it received. No central controller in the loop.

What we measure

  • Resource allocation: task completion and fuel per task
  • Threat perception: debris detection latency and collisions
  • Strategy convergence: how fast learning curves level off
  • Communication efficiency: messages per step

Where we test it

  • Team size: 3, 5 and 8 servicers
  • Threat density: low, medium and high debris
  • Link quality: varied comm range and dropout
  • Rigor: 5 seeds per run, IQM with bootstrap confidence intervals
